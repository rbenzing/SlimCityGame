# Repository structure

Where things belong, derived from where they actually are.

## `src/` — see the dependency map for the full rule set

```
src/
├── shared/   contract layer: types.ts, constants.ts, pure geometry helpers
├── core/     generic engine primitives, no city-domain knowledge
├── world/    tile-grid data model + pure logic (roads, terraform, districts, pathfinding)
├── sim/      every stateful system + worker.entry.ts
├── render/   every three.js renderer/mesh builder
├── tools/    the tool state machine + undo stack (not the root tools/ dir — see below)
├── ui/       React component tree + Zustand store
├── app/      main-thread/session glue (mixed-purpose — see architecture-rules.md)
├── data/     catalog.json, roads.json — static data, no code
└── main.ts   the spine; boots all three execution contexts
```

Full per-directory import rules and evidence:
[dependency-map.md](../dependency-map.md).

## `docs/`

```
docs/
├── README.md            front door to the doc set
├── ROADMAP.md            what shipped, what's next, delivery status/dates
├── DESIGN.md             what is deliberately not being built
├── USERGUIDE.md          how to play
├── engineering/          this tree — architecture, contracts, standards
│   ├── adr/              numbered decision records, never rewritten
│   ├── systems/          how one simulation system works inside
│   ├── features/         one document per feature, before it is built
│   └── standards/         this document and its siblings
├── world-sim/            simulation model docs (traffic, transit, utilities, ...)
├── game-design/          gameplay loop, economy, progression, balancing
├── visual-render/        rendering architecture, shaders, lighting, materials
├── ux/                   HUD and interaction design
├── art/                  art direction and asset standards
└── Road Guides/          MUTCD/traffic-engineering reference PDFs (gitignored;
                          kept locally only — see ADR-0013)
```

There is no single monolithic spec file. The product specification is split
across `world-sim/`, `game-design/` and `engineering/` by discipline, and each
folder's `README.md` indexes its own.

[CONTRIBUTING.md](../../../CONTRIBUTING.md)'s "where a fact goes" table is the
authoritative routing rule for which of these a new paragraph belongs in;
this document is only about physical file/folder placement.

`npm run lint:docs` (`tools/check-doc-links.mjs`) checks that every relative
link in every `.md` file under `docs/` and the repo root resolves to a real
file, and treats a link to a directory with no `README.md` as broken. It runs
in CI alongside the other gates, so a rename that orphans a link fails the
build rather than being discovered by a reader following it.

## `tools/` (repository root, distinct from `src/tools/`)

Two kinds of file live here, and the naming makes the difference legible:

- **`*-shots.mjs`** (and similarly-purposed scripts like
  `visual-smoke.mjs`, `audio-check.mjs`, `growth-probe.mjs`,
  `deterministic-town.mjs`) — Playwright harnesses that boot the real game
  in a headless/real browser and drive it to produce screenshots or console
  captures a human (or model) looks at. See
  [testing.md](testing.md#screenshots-not-read-backs) and
  [debugging.md](debugging.md).
- **`shots-<name>/`** directories — each harness's PNG/log output. Gitignored
  (`tools/shots-*/*.png` etc. in `.gitignore`) — the scripts are tracked,
  their output never is.
- **`check-doc-links.mjs`** — the doc-link checker above.
- **`vite-songs-manifest.ts`** — a Vite plugin (imported by `vite.config.ts`),
  the one non-script file in the directory.

## `public/`

Static assets served as-is. Currently just `public/songs/` — player-supplied
music files. The folder and its `README.md` are tracked; the actual
`.mp3`/`.wav` files are gitignored (the game ships no music of its own; a
player drops their own files in via the UI, per `src/app/music.ts`).

## `screenshots/` (repository root)

One tracked hero image (`screenshot-01.png`) that the root `README.md`
embeds. Not to be confused with `tools/shots-*/`, which is harness output
and gitignored — this directory holds a small number of curated,
permanently-tracked images for the project's own README.

## Root-level files

`CONTRIBUTING.md`, `CLAUDE.md`, `README.md`, `CHANGELOG.md` (generated by
release-please — see [commits.md](commits.md)), `LICENSE`, plus the
standard tool configs (`package.json`, `tsconfig.json`, `eslint.config.js`,
`.prettierrc.json`, `vite.config.ts`, `netlify.toml`,
`release-please-config.json`, `.release-please-manifest.json`).
